## How I build

Most of what I publish started as a problem on my own machine: a tunnel that dies and leaves a webhook provider pointing at a URL that no longer exists, dead console windows piling up on the taskbar, database services eating a gigabyte of RAM at every boot. Each repo is the real fix, generalised enough that a stranger can clone it and run it.

Four rules I hold myself to:

- **It ran on the real thing before it was published.** Where a tool touches processes, files or services, the README quotes output from an actual run against a fabricated version of the failure.
- **Tests assert the fix in both directions** — the broken state it must repair, and the healthy state it must not break.
- **Every README has a limitations section.** If a tool cannot do something, the page says so.
- **Written in English, committed plainly, MIT licensed.**
